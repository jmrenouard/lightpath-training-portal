# How-To: Harden CSP, Credentials, and Audit Chain

Read the [Environment and Feature Flags](../../03-reference/configuration/environment-and-feature-flags.md) and [HTTP Routes and JSON API](../../03-reference/api-and-routes/http-routes-and-json-api.md) references before you harden production hosts.

## Preconditions

1. Make sure that you have administrator access to the portal (`jmrenouard@lightpath.fr` or another `admin` account).
2. Make sure that you have shell access to update environment variables and inspect `LMS_DATA_DIR`.
3. Make sure that TLS termination at your reverse proxy passes `X-Forwarded-Proto: https`.

## Safety Instructions

**WARNING:** Delete `initial_admin_credentials.txt` immediately after you rotate the generated bootstrap passwords. Plaintext credential files on disk expose full `admin`, `trainer`, and `student` access.

**CAUTION:** Never insert inline `style=` attributes or `'unsafe-inline'` directives into portal templates or Nginx configs. The strict `style-src 'self'` CSP blocks inline CSS and breaks UI components.

## Procedure

### Rotate First-Boot Passwords and Provision `LMS_CERT_HMAC_SECRET`

1. Read the one-time bootstrap file generated by `JsonStorage::ensureDefaultUsers()`:

```bash
cat "${LMS_DATA_DIR:-storage/data}/initial_admin_credentials.txt"
```

2. Sign in to the portal as `admin`, `trainer`, and `student` and rotate each password via `update_profile`.

3. Delete `initial_admin_credentials.txt` from disk:

```bash
rm -f "${LMS_DATA_DIR:-storage/data}/initial_admin_credentials.txt"
```

4. Generate a 64-character random hexadecimal secret and export `LMS_CERT_HMAC_SECRET`:

```bash
export LMS_CERT_HMAC_SECRET="$(openssl rand -hex 32)"
```

5. Override the development container password (`postgres`) and confirm non-default credentials in your environment config.

6. Restrict `LMS_DATA_DIR` permissions to `0750` on directories and `0640` on JSON files.

### Preserve Strict CSP and Same-Origin Headers

1. Open `php.ini` or your FPM pool config and set strict session parameters:

```ini
expose_php = Off
session.use_strict_mode = 1
session.use_only_cookies = 1
session.cookie_httponly = 1
session.cookie_samesite = Lax
```

2. Make sure that your Nginx or Apache virtual host omits duplicate `Content-Security-Policy` headers.

3. Confirm that PHP emits `style-src 'self'` on portal routes and `Security::sendStandaloneDocumentCspHeader()` only on inline HTML course streams.

4. Run the automated security and reflection audit test suite:

```bash
php tests/test_coverage_audit.php
for f in tests/test_adversarial_b*.php; do php "$f"; done
```

### Verify the SHA-256 Audit Hash Chain

1. Sign in as `admin` and open `?page=admin&tab=audit`.

2. Inspect the SHA-256 integrity badge next to the audit title.

3. Click `export_audit_csv` to export up to `1,000` active and archived monthly (`audit_logs_YYYYMM`) entries.

4. Run the CLI verification check across active logs and monthly archives:

```bash
php -r 'require "src/bootstrap.php"; $cfg = require "config/app.php"; $s = new LightPath\LMS\Core\JsonStorage($cfg["storage_path"]); echo json_encode($s->verifyAuditIntegrity(true), JSON_PRETTY_PRINT) . "\n";'
```

## Verification

1. Make sure that the CLI check returns `"valid": true` and `"broken_links": []`.

2. Inspect HTTP response headers on a live portal route and make sure that `Content-Security-Policy` excludes `'unsafe-inline'`:

```bash
curl -sI "http://127.0.0.1:8080/index.php?page=verify" | grep -iE "content-security-policy|x-frame-options|x-content-type-options"
```

3. Open `?page=admin&tab=system` and make sure that the secrets hygiene probe reports `OK`.

4. Make sure that `initial_admin_credentials.txt` no longer exists inside `LMS_DATA_DIR`.

## Rollback

If a reverse-proxy header change or secret rotation breaks portal access, do this rollback procedure:

1. Remove any added proxy CSP override and reload Nginx or Apache so PHP headers take effect.

2. Restore the prior `LMS_CERT_HMAC_SECRET` value from your password vault if signed verification mismatches occur.

3. If an administrator password reset locks out operations, export `LMS_INIT_ADMIN_PASSWORD` on a local reset or recover from your backup snapshot.

4. If `verifyAuditIntegrity(true)` reports broken links, isolate the modified `audit_logs*.json` archive and restore from the latest verified backup.

**NOTE:** Pre-chain historical entries appear as `legacy_unchained` and do not invalidate the SHA-256 audit chain.
